# Updated Excel Format and LLM Request Builder

## Excel Structure Changes

### Old Format (Single Row)
```
| Issue Key | Summary    | test steps with expected results |
|-----------|------------|----------------------------------|
| TEST-001  | Login Test | Step 1: Navigate... Expected...  |
```

### New Format (Multiple Rows per Test Case)
```
| Issue Key | Summary    | Description | Precondition | Test Step         | Expected Result      |
|-----------|------------|-------------|--------------|-------------------|----------------------|
| TEST-001  | Login Test | Verify...   | Valid creds  | Navigate to login | Login page displays  |
| TEST-001  |            |             |              | Enter credentials | User is logged in    |
| TEST-002  | Search     | Verify...   | Logged in    | Enter search term | Results are shown    |
```

**Key Changes:**
- ✅ One test case = Multiple rows
- ✅ Same "Issue Key" = Same test case
- ✅ "test steps with expected results" removed
- ✅ Replaced with two columns: "Test Step" and "Expected Result"

## Implementation Details

### 1. Data Model

**TestStep.java**
```java
public class TestStep {
    private String stepSummary;    // Maps to "Test Step" column
    private String testData;       // Optional: "Test Data" column
    private String expectedResult; // Maps to "Expected Result" column
}
```

**TestCase.java**
```java
public class TestCase {
    private String key;                  // Issue Key (grouping key)
    private String summary;              // From first row
    private String description;          // From first row
    private String preconditions;        // From first row
    private List<TestStep> testSteps;    // Collected from ALL rows
    // ... other metadata fields
    
    public String toGoalString() {
        // Formats into LLM-ready prompt
    }
}
```

### 2. Excel Reading Logic

**ExcelTestCaseLoader.java** - Key Features:

```java
// 1. Read row by row
for (Row row : sheet) {
    String issueKey = getCellValue(row, "Issue Key");
    
    // 2. Get or create TestCase (grouped by Issue Key)
    TestCase testCase = testCaseMap.get(issueKey);
    if (testCase == null) {
        // First occurrence: Capture metadata
        testCase = new TestCase();
        testCase.setKey(issueKey);
        testCase.setSummary(getCellValue(row, "Summary"));
        testCase.setDescription(getCellValue(row, "Description"));
        testCase.setPreconditions(getCellValue(row, "Precondition"));
        // ... other fields
        testCaseMap.put(issueKey, testCase);
    }
    
    // 3. Add step from current row
    String testStep = getCellValue(row, "Test Step");
    String expectedResult = getCellValue(row, "Expected Result");
    
    if (testStep != null || expectedResult != null) {
        TestStep step = new TestStep(testStep, null, expectedResult);
        testCase.addTestStep(step);
    }
}
```

**Features:**
- ✅ Uses `Map<String, TestCase>` for grouping by Issue Key
- ✅ Metadata captured from first occurrence only
- ✅ All steps collected and added to the same TestCase
- ✅ Maintains step order from Excel
- ✅ Handles null/empty cells safely
- ✅ Supports both "Step Summary" and "Test Step" column names

### 3. LLM Request Format

**Generated by `toGoalString()` method:**

```
Test Case: [Business Rule Validation] Process PO from Unrecognized Customer
Issue Key: TEST-001

Description:
This scenario validates the end-to-end workflow for a Purchase Order sent by 
an unrecognized customer. The process begins with the IDP system ingesting a 
PO via email...

Preconditions:
- Valid customer database is available
- IDP system is running
- HITL interface is accessible

Test Steps and Expected Results:

Step 1:
Action: Navigate to IDP system and ingest PO via email
Test Data: Email: test@example.com, PO: PO12345
Expected Result: PO is received and processed by IDP system

Step 2:
Action: Verify business rule validation fails for unrecognized customer
Expected Result: Document is routed to HITL for manual review

Step 3:
Action: Access HITL interface and manually input correct customer ID
Test Data: Customer ID: CUST001, OpCo: CA01
Expected Result: Customer ID and OpCo are updated in the system

Step 4:
Action: Resubmit from HITL
Expected Result: All business rule validations pass successfully

Step 5:
Action: Verify POE file is generated and submitted to BIS
Expected Result: POE file is submitted and order creation confirmation received
```

## Usage Example

```java
// Load test cases from Excel
TestCaseLoader loader = new ExcelTestCaseLoader("testcases.xlsx");
List<TestCase> testCases = loader.loadTestCases();

// Process each test case (one per Issue Key)
for (TestCase testCase : testCases) {
    System.out.println("Processing: " + testCase.getKey());
    System.out.println("Steps: " + testCase.getTestSteps().size());
    
    // Convert to LLM prompt format
    String llmPrompt = testCase.toGoalString();
    
    // Send to LLM agent
    TestAgent agent = new LlmAgent(llmPrompt);
    
    // Execute test
    // ... execution logic ...
}
```

## Excel Column Mapping

| Excel Column          | Java Field                    | Notes                          |
|-----------------------|-------------------------------|--------------------------------|
| Issue Key             | TestCase.key                  | **Grouping key**               |
| Summary               | TestCase.summary              | From first row only            |
| Description           | TestCase.description          | From first row only            |
| Precondition          | TestCase.preconditions        | From first row only            |
| Test Step             | TestStep.stepSummary          | From every row                 |
| Test Data             | TestStep.testData             | Optional, from every row       |
| Expected Result       | TestStep.expectedResult       | From every row                 |
| Status                | TestCase.status               | From first row only            |
| Priority              | TestCase.priority             | From first row only            |
| TestCase Type         | TestCase.testCaseType         | From first row only            |
| functional category   | TestCase.functionalCategory   | From first row only            |
| component under test  | TestCase.componentUnderTest   | From first row only            |

## Benefits of This Approach

1. ✅ **Clean Separation**: Metadata vs. Steps
2. ✅ **Flexible**: Support unlimited steps per test case
3. ✅ **Maintainable**: Easy to add/remove steps in Excel
4. ✅ **Safe**: Handles null/empty cells gracefully
5. ✅ **Extensible**: Easy to add new columns
6. ✅ **LLM-Ready**: Formatted output optimized for LLM processing
7. ✅ **Grouped**: One LLM request per Issue Key (efficient)
